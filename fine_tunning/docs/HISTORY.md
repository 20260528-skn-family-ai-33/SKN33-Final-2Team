## 최종 모델과 선정 이유

**기존 모델보다 약 10% 우위라고 판단해 V18을 최종 모델로 선택했다.** 업무 목적에 맞춘 답변 구성과 요청 반영, 병합 모델의 배포·버전 관리 편의도 함께 고려했다. 이 문장의 10%는 사용자 확인에 따른 선정 판단이며, 아래 평가자별 실측 점수의 증감률을 뜻하지 않는다.

|---|---|
| 기반 모델 | `Qwen/Qwen3.8-27B` |
| 기반 revision | `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0` |
| 최종 저장소 | [Ssum-mer/qwen3.8-27b-growpath](https://huggingface.co/Ssum-mer/qwen3.8-27b-growpath) |

## 시기별 변경 이유와 판단

### 10월20일 이전 — 운영 경로 구축

규정·자료·학습 입력을 준비하고 파라미터 등록, 학습 실행, 가중치 보존, 고정 입력 답변, 결과 화면으로 이어지는 경로를 구성했다. 이 기간은 초기 구축 이력으로 요약하며, 샘플 검사 통과를 전체 품질 합격으로 계산하지 않았다.

### 10월21~22일 — 원본1,500건과 정밀도 변경

기존 후보의 반복 패턴과 기간·자료 근거 문제를 보완해 1,237건과 보충263건의 원본 기준판을 만들었다. 로드맵1,003건·부분수정197건·나머지5유형 각60건이다. 기존 분할을 합친1,500건 전체가 학습에 사용됐으므로 그 안의 과거 validation/test를 독립 평가셋으로 다시 계산하지 않았다.

H100의 NF4 QLoRA와 B200의 BF16 LoRA는 GPU와 기본모델 정밀도가 함께 달라진 실험이다. 소요시간 차이를 GPU 단일 요인의 속도 향상으로 표현하지 않았다. B200 P01의 누적5에폭도 optimizer·scheduler가 이어진 단일5에폭이 아니라 2+3 구간 학습으로 구분했다.

### 10월23일 — v4 보완과 품질 gate

알려진 비용 계산, 유효 규정 인용, 완료 증거 해석을 보완했다. 입력 길이가 늘면서 최대길이를10,240으로 변경했고, FLA 역전파 컴파일 오류를 확인해 커널 환경을 조정했다. 일부 설명의 개선에도 특정 사례의 기간·시간 증가 회귀가 남아 v4 후속 실험을 차단했다. 해당 v4 결과는 최종 V18과 동일 모델로 취급하지 않는다.

### 10월23~26일 — 27B 프리셋별 원본 실험

원본1,500건을 사용한 P02~P06은 v4 후속 실행과 별개다. 각 프리셋을 새 기본모델에서 독립5에폭으로 실행하고2·5에폭 가중치를 보존했다. 저장 전용 단계의 ‘답변0건’ 기록과 이후 생성된 답변·평가를 날짜별로 구분했다. 과거 P03의3.70/3.85 등은 당시 입력·평가 기준의 기록이며 현재 V18 평가와 하나의 순위로 합치지 않았다.

### 10월26~28일 — 3,000건과 별도4B 비교

원본1,500건을 보존한 채 신규1,500건을 추가했다. 목표·업무 자료·수정 경계의 다양성 확대를 목적으로 했으며 단순 복제·숫자 치환을 독립 다양성으로 계산하지 않았다. 별도 Qwen3.5-4B 러너로 P01~P03을 실행했으며, 이는 최종27B V18의 모델 교체 이력이 아닌 비교군이다.

### 10월28일 — V18 확정·독립 평가·전달

사용자가 최종 모델을27B V18·실제2에폭으로 확정했다. 병합 모델의 고정 revision, config, 인덱스, 공개 파일 목록을 확인했다. 저장된 동일10건에 대해 Codex가 입력·답변을 직접 읽고 기존 Gemini 평가와 별도로 평가했다. Word 양식·문서·환경을 정리하고 원문 SHA·평가 서명과 전달 ZIP을 검증했다.

| 평가·비교 | 결과 | 해석 |
|---|---:|---|
| 기존 Gemini | 3.03/5 | 기존 보고 점수 보존 |
| Codex 직접 평가 | 3.42/5 | 적용 항목의 사례별 평균을 구한 뒤10사례 동일 가중 평균 |
