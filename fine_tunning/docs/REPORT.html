공식 근거·이용 가능성 확인 종료 강좌·무효 자료·누락 메타데이터 등 부적격 후보 배제 일부 근거는 최대30일 유효기간. 자료 유형별 조건 상이
현재 SHA로 결과 제한 수정 전 자료 내용으로 만든 벡터가 재사용되는 문제 차단 누락·오래된 벡터는 오류 처리. 조용한 성공으로 바꾸지 않음

자료 벡터 PK는 (resource_type, resource_id, embedding_model)이다. 자료 종류별 FK가 정확히1개 연결되도록 제약한다. similarities는 요청 자료 키에 대한 정확 코사인 유사도를 반환하며 함수 자체에 고정top-k·임계값은 없다. 최종 추천의 필터·순위와 구분한다.

8,000바이트·문자·토큰의 구분

8,000은 현재 코드의 UTF-8바이트 제한이다. 모델 API의 공식 토큰 최대치와 같은 단위가 아니다. 한글은 일반적으로 글자당 여러 UTF-8바이트를 사용하므로 ‘8,000자’ 또는 ‘8,000토큰’으로 표기하지 않는다. 현재 전달 규정 파일1,552개는 경로+본문의8,000바이트 초과가0개이며, token_count는 전부NULL이다.

규정은 API 입력의 앞부분만 사용하지만 원문·원본 SHA는 전체를 보존한다. 따라서 긴 규정이 생기면 전체 SHA가 같더라도 임베딩에 후반부가 포함됐다고 볼 수 없다. 학습 자료는 축약 후에도 초과하면 오류를 내므로 두 경로를 같은 잘림 정책으로 설명하지 않는다.

RAG 청크와 파인튜닝 샘플의 구분

규정·학습 자료 청크는 검색에 사용하는 외부 근거다. 파인튜닝1,500/3,000건은 messages 형식의 학습 사례이고, max_length7168/10240은 모델 학습 입력의 토큰 길이 설정이다. 청크1,552개·8,000바이트·학습3,000건·max_length10240은 서로 다른 지표다. 현재 청크 상태와 벡터 적재·승인 여부는 DB 실조회 없이 확정하지 않는다.

확정 이력 요약

기존 모델보다 약 10% 우위라고 판단해 V18을 최종 모델로 선택했다. 선정 판단과 평가자별 측정 점수는 구분한다.

상세 이력은 **HISTORY.md**에 요약 표와 시기별 설명으로 분리했다. 10월20일 이전은 초기 구축 과정으로 간략 정리하고, 이후27B 실험·데이터 변경·4B 비교·V18 확정·평가 근거를 기록했다. 사후 예정 실험은 기재하지 않았다.

서빙 준비 절차

현재 프로토콜을 유지하는 Ollama 경로

  1. 담당 GPU 호스트에서 설치 Ollama 버전이 게시 config의 Qwen3_5ForConditionalGeneration과 tokenizer·chat template를 지원하는지 확인.
  2. 고정 HF revision의 전체 모델을 별도 경로에 확보하고 manifest·샤드 수 확인. 이번 작업에서54.71GB 가중치를 다운로드하지 않음.
  3. 공식 Safetensors import 안내에 따라 모델 디렉터리를 FROM으로 지정한 Modelfile과 ollama create growpath-v18 -f Modelfile 사용. 지원되지 않는 아키텍처면 임의 config 수정·다른 모델 대체 없이 중단.
  4. import와 최소 출력 검증 후 실제 별칭을 .env의 OLLAMA_MODEL_ROADMAP에 기록. OLLAMA_MODEL은 검증된 일반 역할 모델명, 주소·키는 실제 서빙 값. 아직 준비되지 않은 별칭을 설정하지 않음.
  5. 모델이 호출되더라도 위 입출력 변환·시간/비용·수정 보존 검증이 별도로 필요. 규정 검색 임베딩은 기존 OpenAI1536차원 계약 유지.

HF 그대로 사용하는 OpenAI 호환 서빙 경로

vLLM 지원 모델 목록과 Qwen 계열 안내를 기준으로 해당 아키텍처 지원 버전을 별도 Linux GPU 환경에서 고정. Windows 앱용 Conda에 학습·서빙 CUDA 패키지를 섞지 않음. 예시 명령은 실제 GPU 호스트·권한·메모리 확인 후 담당자가 실행할 인터페이스 참고:

vllm serve Ssum-mer/qwen3.8-27b-growpath   --revision 66d1af509ab0681f3b9365227e5c794c65801fbf   --served-model-name growpath-v18 --dtype bfloat16   --max-model-len 7168 --host 127.0.0.1 --port 8000

현재 백엔드의 OPENAI_BASE_URL은 채팅과 임베딩에 공유됨. 이를 생성 전용 vLLM 주소로 바꾸면 규정 임베딩 호출까지 같은 서버로 가므로, 채팅/임베딩 endpoint 분리 없이 단순 설정 변경하지 않음. 입출력 변환과 endpoint 분리에는 백엔드 담당자 검토·이슈/PR가 필요하며 이번 로컬 환경 작업에서 등록·통합 완료로 표시하지 않음.

이전 종료 Pod 재접속·재시작·GPU 구매·유료 API·새 추론 없음. 서빙 절차를 적었다는 사실과 실제 V18 실시간 서비스 연결 완료를 구분.
