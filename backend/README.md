# backend — 5차 FastAPI 백엔드 사본 (참고·로컬 실행용)

화면 개발에 필요한 API를 로컬에서 띄우기 위한 **5차 목업 백엔드 사본**이에요. 팀원 백엔드가 준비되면 `docker-compose.yml`의 `backend` 서비스(또는 `frontend/.env.local`의 `API_PROXY_TARGET`)만 바꿔 끼워요. 2026-10-29 사용자 요청으로 이 사본의 챗봇에 로컬 RoBERTa 질문 분류를 연결했어요. 팀원 백엔드에도 반영됐다는 뜻은 아니에요.

## 들어 있는 것

| 폴더 | 내용 |
| --- | --- |
| `app/` | FastAPI 앱(라우터·서비스·에이전트·관리자 엑셀) |
| `tools/setup_db.py` | 팀 DB 백업 복원 뒤 보조 스키마(app_ext)·보충 자료를 넣는 스크립트 |
| `db/` | 보조 스키마 SQL |
| `web/` | 5차 옛 화면(새 React 화면과 나란히 비교하는 용도 · <http://localhost:8815>) |

## 목표 후보 사전 준비

로그인과 세션 조회에서는 목표 생성 요청을 하지 않아요. 홈페이지에서 본인 입력 저장·되돌리기·평정 동의 또는 관리자 수정/업로드가 성공한 뒤, 추천 입력이 바뀐 직원만 백그라운드로 갱신해요. 부서명·상위 부서 변경과 보유 자격명 변경도 영향을 받는 직원을 포함해요. 목표 화면은 후보가 없는 계정만 처음 준비하고 기존 후보는 그대로 읽어요. 동시 요청은 한 작업을 공유하며 실패하면 이전 후보를 보존하고 사용자가 다시 시도해요. SQL로 직접 수정한 경우에는 명시적으로 후보를 다시 만들어요.

목표 후보의 생성 기준은 `app/agents/goals.py`의 `G_SYS`와 `_api`예요. 앱과 사전 생성 도구 모두 같은 서비스를 사용해요. 모델에는 이름·이메일·사번을 보내지 않고, 소속·직급·직무와 입력된 업무 설명·경험·기술·자격·교육·프로젝트를 전달해요. 평정은 본인이 활용에 동의한 정보만 포함해요. 본인 입력이 없어도 사내 기본 정보가 있으면 실제 모델로 기초 학습 방향을 제안하고, 근거가 전혀 없을 때만 기본 후보를 사용해요.

모델에는 실제로 채워진 항목 이름을 `availableBasis`로 명시해요. 서로 다른 후보 3개, 각 8~160자이고 `싶어요.`로 끝나는 문장, 비어 있지 않은 추천 이유와 실제 제공된 항목의 근거를 검사해요. 입력 문장 안의 지시는 따르지 않으며, 없는 업무·경력·자격·프로젝트를 만들지 않도록 지시해요. 형식·근거 항목 검사는 사실 검증 전체를 대신하지 않으므로 결과도 프로필과 대조해야 해요. 검사 실패를 고정 후보의 성공으로 바꾸지 않고 이전 후보를 보존해요. 실제 모델 호출과 무료 고정 응답 검증은 별도로 기록해요.

DB 공유 전에 미리 생성할 수도 있어요. `backend/`에서 실제 앱 DB 설정과 `db/02_app_ext.sql`을 준비한 뒤 대상 ID를 지정해요. 아래 ID는 예시이므로 실제 확인한 `employee_id`로 바꿔요. 원문·비밀번호·키는 출력하지 않아요.

```powershell
$preloadEmployeeId = 123  # 예시 ID
python tools/preload_goals.py --employee-id $preloadEmployeeId
# API/GPU 사용 범위를 승인받은 뒤에만 실행. 여러 명은 --employee-id를 반복해요(기본 최대 4명).
python tools/preload_goals.py --employee-id $preloadEmployeeId --provider ollama --apply
```

기본 실행은 조회만 하며 추론/DB 쓰기가 없어요. `--apply`는 생성이 필요한 대상만 처리하고 `--provider openai`는 유료 API를 사용해요. `mock`은 가데이터로 표시되며 실제 추론으로 계산하지 않아요. 실패한 같은 입력은 자동 재시도하지 않으므로 화면의 다시 만들기를 사용해요. 기존 유효 후보는 모델을 지정해도 재사용해요.

완료 후 `public.employee_recommended_prompts`와 `app_ext.goal_suggestion_meta`·`goal_suggestion_runs`를 포함한 **전체 DB 백업**을 공유해요. 후보뿐 아니라 이유·입력 해시·상태도 있어야 수신 PC 로그인에서 같은 후보를 재사용할 수 있어요. 업무 설명의 구판 값이 남아 있으면 새 앱이 읽기 호환을 유지하며, 선택 이관 SQL은 백업/충돌 확인 후 명시적으로 실행해요.

## Track 프롬프트 DB 연결 (#38)

Free Track(A1→agent_certified), Fast Track(A2→agent_fasttrack), Challenge Track(A3→agent_practical)은 `public.prompt_versions`의 활성 버전을 매 요청 읽습니다. 기존 agent_id는 유지하며, 이름 변경 전 버전도 보존합니다. 각 본문은 `### GENERATION`과 `### REVISION` 구역으로 나뉩니다. 활성 버전 누락·중복·형식 오류는 명시적으로 실패하며 코드 기본값으로 대체하지 않습니다.

새 환경에서는 기존 DB 백업을 보관한 후 아래 순서로 적용합니다. 모델 호출은 발생하지 않습니다.

```bash
docker compose up -d --no-deps --build backend
docker compose exec -e PYTHONPATH=/srv/growpath backend python tools/install_track_prompts.py
docker compose exec -e PYTHONPATH=/srv/growpath backend python tools/test_track_prompts.py
```

등록 도구는 이전 활성 버전을 비활성화하고 부모 버전에 연결한 새 버전을 트랜잭션으로 활성화합니다. 같은 내용으로 재실행하면 새 버전을 만들지 않습니다. Free Course의 강좌는 비용이 0으로 확인된 자료만 전달하고, 유료·비용 미확인 강좌를 반환하면 서버에서도 거부합니다. 도서는 가격과 관계없이 허용하며, 기존 DB 활성 프롬프트 뒤에 이 도서 예외 정책을 덧붙입니다. 실제 AI 생성 품질 검증은 별도입니다.

프롬프트를 되돌릴 때는 `prompt_versions`에서 이번 변경의 활성 버전·`parent_version_id`를 확인하고, 해당 agent_id의 현재 버전을 비활성화한 뒤 부모 버전을 한 트랜잭션에서 활성화합니다. **백엔드 코드도 해당 이전 정책을 사용하던 버전으로 함께 되돌립니다.** DB 연결 도입 전 버전은 구역 형식도 달라 호환되지 않습니다. 개인 로드맵 제목 데이터는 이 등록 도구가 변경하지 않습니다.


### Free Track 후속 경계 처리 (#38 / PR #41)

Free Course만 후보 순위·개수 제한·본문 용량 배분 전에 강좌의 비용 0 조건을 적용합니다. 도서는 가격과 관계없이 허용합니다. 시연 생성·재생성·수정은 유료·가격 미확인 강좌를 제외하고 이유를 남깁니다. 모델 출력의 마지막 무료 검증은 유지합니다.

최초 확정과 수정안 적용은 저장 트랜잭션에서 `app_ext.resource_meta.cost_won`을 직접 조회하고 가격 행을 잠급니다. 유료·NULL 강좌 또는 종류와 관계없이 삭제된 자료가 섞이면 `409 FREE_TRACK_PRICE_CHANGED`로 저장을 거부하며 계획을 조용히 바꾸지 않습니다. Fast/Challenge Track의 후보 선정과 가격 처리는 유지합니다. DB 스키마·프롬프트 재설치는 필요하지 않습니다.

회귀 검사는 백엔드 디렉터리에서 `PYTHONPATH=. python -m unittest discover -s tests -p test_free_track_regressions.py -v`로 실행합니다. 실제 모델 호출이나 DB 쓰기를 하지 않고 생성·재생성·수정·확정·수정안 적용과 다른 Track 무영향을 확인합니다.

삭제된 자료는 실제 행 삭제와 content_status=deleted 표시를 모두 확인합니다. Free 활동 저장 시 카탈로그를 갱신하고 검증된 0원을 활동별 비용에도 반영합니다.

예전 Free 계획에 완료한 유료 강좌 활동이 남아 있어도 무료 강좌 정책의 예외는 없습니다. 유료·가격 미확인 도서는 허용하며 확인된 도서 가격은 합산하고 미확인 가격은 별도 표시합니다. 수정안 적용은 409로 거부하며 무료 자료로 다시 생성하거나 다른 Track을 선택하라는 메시지를 화면에 전달합니다. 기존 기록이나 활동을 자동 삭제하지 않습니다.

### 스킬별 사전 점검 (#47)
프로젝트/희망 역량에서 DB 스킬을 최대 5개 선정하고, 개인 DB 프로필과 기획서 요약(선택)을 참고해 사전 점검을 생성합니다. 스킬 1개는 설문 5개+퀴즈 5개, 2~5개는 스킬마다 설문 3개+퀴즈 3개입니다. 퀴즈는 5지선다이며 전체 설문 후 전체 퀴즈를 진행합니다.

- 원본 API: `GET /api/v2/drafts`, `GET/POST /api/v2/drafts/{project_id}/survey`, `PUT /api/v2/drafts/{project_id}/survey/answers`.

### 구형 미확정 초안 정리 (#55)

새 사전 점검 정보가 없는 이전 방식의 미확정 초안은 조회·백업 후 DB에서 정리하고 새 방식으로 다시 작성합니다. 자료 선택·검토를 우회하는 새 호환 분기는 추가하지 않습니다. `tools/cleanup_legacy_drafts.py`는 기본으로 조회만 합니다. `DRAFTING`이면서 이전 문항이 저장돼 있고 `v2Survey`·새 점검 handoff가 없는 초안만 후보입니다. 새로 입력 중인 빈 초안, 확정 로드맵·보고서·사후 평가가 연결된 기록은 보존합니다.

```bash
# backend 기준. var/는 Git 제외이며 조회 결과와 백업을 개인 자료로 보관합니다.
python tools/cleanup_legacy_drafts.py --output var/legacy-drafts/review.json
python tools/cleanup_legacy_drafts.py --apply var/legacy-drafts/review.json --backup var/legacy-drafts/backup.json
# 같은 DB·스키마에서 삭제 전 상태로 복구할 때만 실행합니다.
python tools/cleanup_legacy_drafts.py --restore var/legacy-drafts/backup.json
```

적용은 조회 파일에 명시한 프로젝트 ID만 행 잠금 후 재검사합니다. 조회 뒤 내용·상태가 바뀌었거나 보호할 기록이 생기면 삭제를 중단합니다. 기존 백업 파일을 덮어쓰지 않으며 초안·해당 사전 점검 기록을 디스크에 보존한 뒤 같은 트랜잭션에서 삭제합니다. 알 수 없는 관련 테이블이 있으면 범위를 추정하지 않고 중단합니다. 복구는 같은 DB와 원래 스키마를 전제로 하며 기존 행·외래키와 충돌하면 전체 롤백합니다. 조회 결과가 0건이면 실제 삭제도 0건입니다. 이 도구는 앱 시작·DB 초기화·CI에서 자동 실행하지 않습니다.

관련 무료 검사: `python -m unittest discover -s tests -p test_legacy_draft_cleanup.py -v`, `python -m unittest discover -s tests -p test_resource_evidence.py -v`.

### 스킬별·Track별 강좌 후보 (#47)

로드맵 생성·재생성·수정은 `catalog_candidates.py`와 `catalog_budget.py`를 사용합니다. 전체 강좌에서 스킬별로 최대 20개를 검토합니다. Fast는 앞쪽 핵심 스킬 최대 3개·60개 강좌, Free/Challenge는 최대 5개·100개 강좌입니다. 여러 스킬에 연결된 같은 강좌는 중복 슬롯을 소비하지 않고 다음 후보로 채웁니다. 기존 선택 자료는 별도로 우선 보존하며 도서·공식 문서는 보조 후보 최대 4개입니다. 보조 자료도 동일한 관련성·적합도 순위에 따라 배치하고 앞쪽 고정 슬롯을 주지 않습니다. 실제 AI 전달 상한은 모든 자료를 합쳐 기본 32개입니다. 스킬이 4~5개이거나 필수 선택 자료가 32개를 넘는 경우에만 최대 40개를 시도하며, 후보 부족·입력량 한도에 따라 줄어들 수 있습니다.

Free는 강좌에만 비용이 확인된 0원 조건을 적용하며 도서는 유료·가격 미확인도 검색·선택·확정할 수 있습니다. Fast/Challenge는 `관련성 × (1 + 관점 적합도)`로 순위를 정합니다(적합도 0~1). Fast는 목표 관련 단원의 비율·직접 구현과 짧은 시간을 함께 평가합니다. 확보한 유효 단원이 6개 이상이고 목표 관련 단원이 1/3 미만인 일반 강좌는 Fast에서 제외합니다. 단원이 적거나 미확보인 경우 이 비율만으로 제외하지 않고, 사용자가 명시적으로 선택한 자료는 보존합니다. 자동 선정의 핵심 3스킬 지침과 사용자 확정 최대 5스킬 유지를 구분합니다. 모든 코스에서 기간 상한을 적용하지 않고 실제 자료 시간으로 예상 기간을 계산합니다. 기간보다 긴 강좌나 시간 미확인 강좌를 시간만으로 제외하지 않으며 Crash는 짧은 고유 강좌 조합을 우선합니다.

Challenge는 DB 활성 프롬프트에 맞춰 목표 관련 단원의 **설계·성능 측정·문제 해결**을 단순 구현·배포 반복보다 높게 평가합니다. 심화 단원 수(4개에서 상한)와 세 행동의 다양성이 적합도의 55%, 기존 실무 행동 다양성과 단원 수가 각각 10%입니다. 확보된 목차에 목표 관련 심화 단원이 둘 이상이면 중급·고급 난이도에 심화 근거 비례 가점(최대 20%·25%)을 더합니다. Beginner와 난이도 미확인 자료도 같은 심화 근거를 인정합니다. 유효 단원이 6개 이상인데 심화 근거가 둘 미만이면 **난이도 표시와 관계없이** 점수를 0.8배로 낮추며 제외하지는 않습니다. 명시적으로 선택한 자료는 보존합니다. Fast의 집중도 하한은 적용하지 않습니다.

집중도·실무 깊이·발췌 순위는 개별 수업 제목·설명을 기준으로 하며 섹션 제목의 행동을 하위 수업에 반복 인정하지 않습니다. 단원을 확보했으면 소개의 홍보 문구로 실무 깊이를 추가하지 않고, 목차 미확보 시 소개 기반 적합도 기여는 1/4로 낮춥니다. 중복 단원과 수강 만족도·강의 평가, 선수지식 구역은 제외합니다. 문서 10건·질문 20개 같은 수량을 수업 번호와 매칭하지 않으며, 일반적인 구현·모델·점검 단어만으로 무관한 심화 수업에 가점하지 않습니다. 단어 규칙이므로 문맥이나 모든 한국어 조사·동의어를 이해하는 의미 검색은 아닙니다. 일반 후보의 목표 관련성은 양수여야 하며, 중복률을 낮추기 위한 강제 배제·난이도 할당량은 없습니다. 학습자 수준은 임의로 Beginner/Advanced로 변환하지 않고 기존 `known`·`gaps`·`deepCheck`를 LLM에 유지해 최종 선택·편성에 반영합니다. 구판 진단 후보 생성과 시연 고정 응답은 이번 변경 범위에 포함하지 않습니다.

관련성 판단은 제목, 소개(`curriculum.description`/`syllabus_summary`, 관리자 수정값 우선), 단원별 제목·섹션·설명을 사용합니다. 명시된 선수지식·학습대상·강사 소개 구역, 중지 단원과 제목 누락 단원은 학습 근거에서 제외합니다. 태그가 같아도 제목·학습 본문에 목표 관련 검색 근거가 없으면 일반 후보에서 제외하며, 그 대신 무관한 자료로 개수를 채우지 않습니다. 사용자가 명시적으로 고른 자료는 기존 우선 보존 규칙을 따릅니다. 혼합 문장에 숨은 선수지식을 모두 판별하는 의미 분석은 아니므로 실제 추천 품질 검토는 별도로 필요합니다. 정규화된 검색 본문은 기존 카탈로그 스냅샷이 바뀔 때 재구성하며 DB 갱신 후 카탈로그 무효화/기존 120초 TTL을 따릅니다.

각 후보에는 관련 단원 1~2개(각 최대 50자) 또는 소개 원문 발췌(최대 100자)가 들어갑니다. Fast는 관련 구현 단원, Challenge는 관련 구현·검증·개선·운영 단원도 발췌 순위에 반영합니다. 원문 위치는 `curriculum`의 `[0부터 시작하는 단원 위치, 발췌]`로 전달합니다. 전체 목차를 전달한 것으로 취급하지 않습니다. 근거가 없으면 `evidenceStatus=unavailable`로 표시합니다. 반복 메타데이터는 `catalogDefaults`, 스킬명은 `catalogSkillMap`으로 한 번만 보냅니다. 이 입력 형식은 `catalogPolicy`로 설명합니다. Fast/Challenge의 후보 선정 취지는 `trackGuidance.candidatePreference`로 전달하며 활성 DB 시스템 프롬프트를 변경·대체하지 않습니다. Fast의 핵심 스킬·관점 지침은 `trackGuidance`에 전달하며 `handoff.prefs.deadlineWeeks`는 참고 값으로 보존하고 6주로 잘라내지 않습니다. 저장된 사용자 설정은 바꾸지 않습니다. 단원 관련성 집계는 자료당 최근 질의 최대 4개를 캐시하고 변경된 자료의 캐시만 폐기합니다. DB 테이블과 화면 구성은 바꾸지 않습니다.

실제 진단 전달부 `build_handoff`는 목표·진단 텍스트에서 DB에 등록된 스킬 이름을 최대 5개 추려 `handoff.skillNames`에 기록합니다. 키워드 규칙 기반 연결이며 별도 의미 모델의 판단은 아닙니다. Fast는 그중 앞쪽 최대 3개를 검색하고 LLM에도 같은 핵심 스킬 목록을 보냅니다. 구판 handoff에 이름이 없으면 동일 규칙으로 추정합니다. `trackPolicyVersion`을 캐시 키에 포함해 정책 변경 후 예전 생성 안을 그대로 재사용하지 않습니다. `handoff.selectedResourceIds`, 기존 계획 자료, 사용자가 선택한 자격은 우선 보존합니다. Free에서 유료·가격 미확인 강좌는 제외하고 도서는 허용하며 `catalogExcluded`에 남깁니다. 삭제/추천 불가인 필수 자료, 필수 자료 40개 초과, 입력량 초과는 명시적으로 실패합니다. 진단의 `resourceHints`는 스킬별 검색 범위 안에서 우선 검토하고 개수 제한을 우회하지 않습니다.

저장된 `handoff.skillNames` 중 현재 카탈로그에 남은 이름만 순서대로 사용합니다. 전부 이름이 바뀌거나 삭제됐거나 빈 목록이면 목표·프로젝트·진단 텍스트에서 현재 스킬 이름을 다시 추정합니다. 모든 안의 모델 입력에도 정리한 이름을 전달하며 저장된 원본은 수정하지 않습니다. 추정 근거가 없으면 없는 스킬을 만들지 않고 빈 후보를 허용합니다. 목록 형식 오류와 남아 있는 스킬 5개 초과는 오류입니다.

기존 계획의 삭제·추천 불가 자료는 완료 여부와 관계없이 자동으로 빼지 않습니다. 모델 호출 전에 오류에 현재 자료명과 ID를 표시하며, 원본이 삭제돼 이름이 없으면 기존 활동명과 ID를 표시합니다(최대 5개와 추가 개수). 대상을 찾을 수 있도록 안내한 뒤 활동 삭제·교체 또는 자료 선택 해제로 다시 요청하게 합니다. 이는 완료 이력의 자동 제외·복원까지 구현한 것은 아닙니다. Free의 유료·비용 미확인 강좌 제외와 도서 허용, 확정 시점 검사는 기존 정책을 따릅니다.

Fast의 핵심 학습 스킬(`handoff.skillNames`·`trackGuidance.coreSkills`)과 과제 분류용 `skillTags`는 구분합니다. 생성·다시 만들기·수정안 모두 DB의 전체 태그 목록을 보존하여 Docker·MLOps 과제를 핵심 3개 중 무관한 태그에 억지로 맞추지 않게 합니다. 실제 과제에서 수행하는 스킬만 1~3개 붙이며, 보조 태그 때문에 별도 학습 스킬·과제를 늘리지는 않도록 입력에 명시합니다. 등록되지 않은 태그 제거와 과제당 3개 제한은 유지합니다. 정책 버전을 올려 이전 제한으로 생성한 후보 캐시를 재사용하지 않습니다. 확정한 로드맵의 기존 태그를 자동 수정하는 작업은 포함하지 않습니다.

입력량은 `Qwen/Qwen3.8-27B` revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`의 공개 토크나이저로 CPU에서 계산합니다. 가중치나 추론 호출은 필요 없습니다. 후보 입력 5,000토큰(확장 시 6,000), 시스템·handoff·기존 계획·수정 요청을 합친 입력 10,000토큰을 상한으로 두며 채팅 포장 여유 128토큰을 더합니다. 설정된 Ollama 문맥이 16,384보다 작으면 출력 4,096과 여유 2,048을 먼저 빼고 상한을 줄입니다. 이는 배포된 Ollama 템플릿·생각 길이 전체의 보증이나 OpenAI의 정확한 과금 토큰 수가 아닙니다. 입력 본문/필수 자료를 조용히 자르지 않으며 여유가 없으면 후보를 줄이거나 안내 오류를 반환합니다.

### 후보 준비 성능 (#55)

카탈로그의 기존 120초 TTL과 관리자 갱신 후 무효화를 유지합니다. 새 스냅샷의 자료별 전체 값이 같으면 정규화한 소개·목차와 최대 4개 질의 집계를 재사용하며, 변경·추가된 자료만 다시 구성하고 삭제된 자료는 새 색인에서 뺍니다. 가격·시간·상태·스킬 변경도 비교에 포함합니다. 새 색인은 최신 행을 별도로 연결하고 진행 중인 요청이 쓰는 이전 스냅샷을 수정하지 않습니다. 요청 도중 공유 자료를 직접 수정하는 사용 방식은 지원하지 않습니다.

서버는 요청 수락 전에 스레드에서 `catalog.warmup_roadmap()`으로 카탈로그·색인·고정 토크나이저를 준비합니다. 이 비용은 서버 시작 시간에 들어가며 모델 생성·임베딩·DB 쓰기는 하지 않습니다. 사전 로딩 실패는 오류 로그로 남기고 서버는 시작합니다. 로드맵 요청은 기존 파일·후보 검사를 다시 수행하므로 누락 파일을 성공으로 처리하지 않습니다.

로드맵 생성·다시 만들기·수정안의 실제 모델 입력은 JSON 구분자 공백만 제거합니다. 값·키 순서·문자열 내부 공백은 보존하며 다른 에이전트의 입력 형식은 유지합니다. 후보 수·순서를 늘리지 않도록 입력 한도 판단은 기존 공백 포함 표현을 그대로 사용하고, 실제 전송량은 검증 도구에서 별도로 확인합니다. 최적화 전후의 의미가 같은 입력이라도 실제 LLM 응답이 완전히 같다는 보장은 없으므로, 후보·기존 응답 재처리 비교와 신규 모델 평가는 구분합니다.

외부 연결 없는 관련 검사는 `python -m unittest discover -s tests -p test_catalog_performance.py -v`로 실행합니다. 기존 전체 회귀 검사와 실제 DB 18사례 검사도 위 명령을 따릅니다.

### 로드맵 생성 시간 초과 조정 (#47)

`OPENAI_ROADMAP_TIMEOUT`은 OpenAI 로드맵 생성·재생성·수정 요청의 HTTP 대기 제한입니다. 기본 180초, 설정 범위 1~600초이며 잘못된 값은 시작 시 오류로 알립니다. 다른 OpenAI 기능은 기존 90초, 연결 확인은 15초, Ollama는 기존 `OLLAMA_TIMEOUT`을 사용합니다. 설정 변경 후 백엔드를 재시작하며 90으로 설정하면 이전 제한으로 돌아갑니다. HTTP 대기 제한은 전체 작업의 정확한 종료 시각이나 외부 프록시 제한을 보장하지 않습니다.

강좌 후보는 기본 32개·최대 40개와 기존 근거·입력 한도를 유지합니다. 사용자 추론 정도를 자동으로 낮추지 않습니다. 기존 AI 모델 설정에서 고른 값이 우선하며, 없으면 `OPENAI_REASONING_EFFORT`, 그것도 없으면 모델 기본값을 따릅니다. `low` 비교는 동일 목표·후보·DB 프롬프트에서 별도로 검증하고 품질과 소요 시간을 함께 기록합니다. 이 설정은 대기 중 실패를 줄이기 위한 것으로 생성 속도 개선을 보장하지 않습니다.

실패한 안만 사용자가 재시도하는 기존 동작과 성공한 안의 보존을 유지합니다. 자동 유료 재호출은 추가하지 않습니다. PR #46의 무료 필터·저장 직전 가격 검사는 A1에만 적용되며, Fast(A2) 생성의 추가 LLM 호출이나 가격 잠금은 없습니다. 과거 Fast 6주·핵심 3스킬 비교 기록은 당시 조건의 관찰이며 현재 기간 상한 해제·사용자 확정 스킬 유지 정책과 구분합니다. 비교를 위해 DB 프롬프트나 실제 사용자 설정을 바꾸지 않습니다.

무료 검사: backend에서 `python -m unittest discover -s tests -p test_reasoning.py -v`로 역할별 제한·사용자 추론값 유지·설정 경계·시간 초과 시 1회만 호출함을 확인합니다. 전체 회귀 검사는 위의 `python -m unittest discover -s tests`를 사용합니다. 실제 유료 호출은 별도 합의된 범위에서만 실행합니다.

### 프로젝트 학습 흐름과 main 후보 정책의 연결 (#47)

### 학습 흐름 개편 (#59, 2026-11-03)

목표·기획 → 세부사항·스킬 선택 → 입력 확인 → 역량 테스트 → 결과 → 로드맵·자료 선택 → 검토·산출물 선택·확정의 7단계다. 스킬은 목표·프로젝트 요약·개인 프로필로 제안하고 드래그/화살표로 순서를 정한다. 입력 확인 진입 시 선택한 스킬의 문항을 백그라운드에서 준비하며 상태 문구는 표시하지 않는다. 완료한 응답은 앞단 입력을 변경하기 전까지 고정한다.

입력 확인은 하나의 박스 안에 학습 목표·프로젝트 요약(더보기)·세부사항·선택 스킬을 구분선으로 표시한다. 목표 단계는 요약 본문을 중복 표시하지 않는다. 결과는 같은 설문·퀴즈를 읽기 전용으로 표시하고 설문은 테마색 선택 강조만 사용한다. 퀴즈의 선택 정답은 초록, 선택 오답은 빨강, 오답 시 실제 정답은 파랑이며 문항 번호에도 정오답을 표시한다.

테스트 완료 응답을 저장한 직후 로드맵 생성을 시작한다. 각 코스가 준비되면 자료 추천도 백그라운드에서 시작한다. 자료 비교는 공통 스킬 탭 아래 Free·Crash·Challenge를 나란히 표시하며 세 코스의 추천이 완료되면 함께 공개한다. 접기·펼치기는 생성 요청이 아니다. 코스 선택은 해당 코스의 추천 ID와 선택 자료를 유지한다. 로드맵 재생성에 성공한 경우에만 해당 코스 자료를 무효화하고, 재생성 중 낡은 조건으로 추천을 시작하지 않는다.

자료를 저장하면 산출물 생성 완료를 기다리지 않고 검토로 이동한다. 선택한 책·강좌와 기존 산출물은 먼저 읽어 표시하고, 없는 산출물·역량 요약만 생성한다. 계정·초안·입력·코스·자료별 작업을 분리하고 같은 요청은 공유한다. 늦은 응답과 중복 확정은 차단한다. 홈의 공통 강좌는 여러 스킬의 배정 범위에 연결해 표시한다. 사후 점검·조기 종료 버튼은 각 로드맵의 활동 카드 안에 둔다.

전체 코스의 기간 상한은 현재 제거했다. 주당 시간 검증과 실제 자료 시간 기반 예상 기간 계산은 유지한다. 기간 정책은 구조 개편 이후 팀 논의로 결정할 후속 항목이다. 기간 경과에 따른 자동 완료는 사용자 요청으로 구현 범위에서 제외했다.

현재 단계에 맞는 고정 스킬·Challenge targetOutcome/completionCriteria 계약을 실행 프롬프트에 추가했으며 DB 프롬프트 원문은 변경하지 않았다. 후보 부족과 최종 모델 미선정을 구분해 안내한다. 강좌는 후보 최대 6개에서 모델이 최대 3개 선별하므로 2개 고정 제한은 없다. 실제 모델의 새 응답 품질·Crash 도서 미선정 원인은 별도 검증이 필요하다.

검증: 백엔드 411개·프롬프트 6개·프런트 168개, 타입·린트 오류 0개(기존 Fast Refresh 경고 41개)·빌드. 단위 검사는 실제 DB에 연결되지 않는 주소로 실행했다. 실제 모델·부하·다중 서버·전체 화면 시나리오 검증과 월간 자동 개선 운영 검증은 완료로 간주하지 않는다. DB 스키마·마이그레이션 변경 없음.

동일 강좌 정책: 같은 로드맵의 동일 강좌는 관련 스킬의 전체 배정 주차 범위로 표시하고 가격은 자료 ID별 한 번만 합산한다. 각 스킬에 강좌 내용을 그대로 유지하며 분할하지 않는다. 진행 기록 저장 시 해당 강좌의 상태를 함께 반영하되 스킬별 메모·첨부는 보존한다. 도서·과제·다른 로드맵에는 전파하지 않는다. 실 DB 일괄 변경·스키마 변경은 실행하지 않았다. Crash 중복을 인접 스킬로 한정하는 방안은 후속 이슈에서 검토한다.
