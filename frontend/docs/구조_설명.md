# 구조 설명

5차 목업(화면 스크립트 11개 + CSS 3개, 전역 `GP` 객체로 서로 연결)을 React + Vite + TypeScript로 옮긴 구조와 그 이유, 5차 파일과의 대응을 적어요.

## 한눈에 보기

```text
(저장소 맨 위)
├─ docker-compose.yml        DB · 백업 복원 · 보충 자료 · 참고용 백엔드 · 화면(nginx)
├─ .env.example              도커·백엔드 설정 예시(가짜 값)
├─ team_db/                  팀 DB 백업 넣는 곳(백업 파일은 Git 제외)
├─ scripts/db-restore.sh     빈 DB일 때만 백업 복원
├─ backend/                  5차 FastAPI 사본(참고용 · 팀 합의로 함께 둠 · 팀 백엔드가 준비되면 교체)
└─ frontend/
   ├─ docs/                  이 문서 · API 계약
   ├─ Dockerfile · nginx/    빌드 → nginx 가 정적 파일 + /api 넘기기
   ├─ vite.config.ts         개발 서버(/api 프록시) · 빌드 · 테스트 설정
   └─ src/
      ├─ main.tsx            시작점(CSS → 서버 데이터 캐시 → 라우터)
      ├─ app/                주소(paths) · 라우터(routes) · 앱 틀(layout) · 서버 데이터 캐시(queryClient)
      ├─ api/                서버 호출의 유일한 자리: client · jobs · endpoints/* · types/*
      ├─ shared/             여러 기능이 함께 쓰는 것
      │  ├─ constants/data.ts   화면 고정 자료(5차 gp-data.js)
      │  ├─ lib/                순수 계산(로드맵 주차·비용, 형식, 규정 조항, 세부 사항 글자)
      │  ├─ state/              전역 상태(계정·작업 공간·AI 모드·자료 캐시·창·테마·입력 연결)
      │  ├─ hooks/useGo.ts      화면 이동(이동 확인 가드 포함)
      │  └─ ui/                 공통 조각(Page·Note·OpsBox·창·연결 상태·입력 칸·메뉴 조각)
      ├─ features/           기능별 화면
      │  ├─ auth/ demo/         로그인 · 시연 도구
      │  ├─ draft/              새 로드맵 작성 6단계(goal·details·quiz·result·generation·options·review)
      │  ├─ home/ roadmap/      홈(간트) · 내 로드맵(기록·수정 요청·코멘트)
      │  ├─ assessment/ report/ 점검·사후 점검 · 결과 보고서
      │  ├─ resources/ profile/ 학습 자료 · 내 정보
      │  ├─ skillmap/           스킬 지도
      │  ├─ team/               부서장 화면
      │  ├─ assistant/          사내 생활 도우미
      │  └─ admin/              관리자 화면
      └─ styles/             5차 CSS 3개 그대로(gp.css → gp-v2.css → gp-admin.css 순서)
```

## 왜 이렇게 나눴나

| 결정 | 근거 |
| --- | --- |
| 화면을 React + Vite + TypeScript로 다시 씀 | 5차는 즉시 실행 함수 11개가 전역 `GP`에 함수를 붙여 서로 부르는 구조라, 어느 파일이 무엇에 기대는지 import로 드러나지 않아 여러 사람이 나눠 고치기 어려웠어요. 모듈 import와 타입으로 의존과 API 모양이 코드에 드러나고, 빌드 결과가 정적 파일이라 nginx·S3로 바로 배포돼요. |
| 화면 모양·문구·CSS는 그대로 | 이번 작업은 구조 개편이라 사용자 화면이 바뀌면 안 돼요. 5차 CSS 클래스와 DOM 구조를 그대로 써서 5차 화면과 나란히 비교할 수 있게 했어요. |
| 백엔드는 사본만 두고 고치지 않음 | 백엔드는 팀원 담당이에요. 화면 개발에 필요한 실행 환경으로만 두고(공개 저장소에 맞춰 기본 비밀번호만 뺐어요), 고칠 것은 백엔드 요청 이슈로 넘겨요. |
| 서버 호출은 `api/`에만 | 팀원 백엔드로 바꿀 때 고칠 곳을 한 폴더로 모았어요. 화면 컴포넌트는 `fetch`를 직접 쓰지 않아요. 오류는 `ApiError` 하나로, 오래 걸리는 작업은 `waitJob` 하나로 다뤄요. |
| 상태를 세 가지로 나눔 | ① 서버가 주인인 조회 데이터(부서장 목록·관리자 표·스킬 지도·학습 자료)는 TanStack Query 캐시. ② 작성 중인 로드맵과 확정 로드맵 기록은 zustand `workspace` — 입력할 때마다 서버에 자동 저장(PATCH)하고 서버 응답을 다시 받아 맞춰야 해서 한 곳에 둬요. ③ 창·패널·입력 중인 값 같은 화면 상태는 각 기능의 작은 store나 컴포넌트 state. |
| 주소를 경로로(`/roadmaps/:pid`) | 5차는 해시(`#roadmap:id`)였어요. 경로 주소는 새로 고침·북마크·배포(nginx `try_files`)에 맞고, 화면별 권한·메뉴 강조·폭은 라우트 `handle`로 한 곳에서 정해요. |
| 도커 이름·포트·쿠키를 설정으로 | 같은 PC에서 다른 실행 환경(예: 5차 목업)과 동시에 켜도 서로 덮지 않게 `.env`로 바꿀 수 있게 했어요. |

## 어디에 무엇을 두나

- 새 화면: `features/<기능>/` 아래에 컴포넌트를 만들고 `app/routes.tsx`에 주소와 `handle`(nav·title·width·role)을 적어요. 주소 문자열은 `app/paths.ts`에만 둬요.
- 새 API: `api/endpoints/<영역>.ts`에 함수, `api/types/<영역>.ts`에 요청·응답 타입. 계약이 바뀌면 [API 계약](API_계약.md)도 함께 고쳐요.
- 여러 기능이 쓰는 계산: `shared/lib/`(순수 함수 · 테스트 붙이기 좋은 자리). 한 기능만 쓰면 그 기능 폴더에.
- 테스트: 같은 폴더에 `*.test.ts`. 순수 계산·변환 규칙만 테스트하고 화면 흐름은 브라우저로 확인해요.

## 코드 규칙 (실수하기 쉬운 것)

- zustand 선택자는 같은 값이면 같은 참조를 돌려줘야 해요. `useWs((s) => s.list.filter(...))`처럼 새 배열·객체를 만들면 무한 다시 그리기가 생겨요. 원본 값을 고르고 바깥에서 계산하거나 `useShallow`를 써요.
- 작성 화면 입력은 경로로 묶어요(`shared/state/bind.ts` · 5차 `data-bind`): `BText path="draft.prefs.hours"`처럼 쓰면 고칠 때 자동 저장까지 이어져요.
- 서버 응답을 상태에 넣는 동안 자동 저장이 다시 돌지 않게 `draftSync.ts`가 막아요. 작성 문서를 직접 고칠 때는 `updateWs`를 쓰고, 서버 응답을 넣을 때는 `takeDraft`를 써요.
- 렌더 중에 상태를 바꾸지 않아요(이벤트 처리나 effect에서). 효과 안에서 바로 setState 하는 대신 값을 계산으로 이끌어 내요(ESLint `react-hooks`가 잡아요).
- 화면 문구·CSS 클래스는 5차와 같게 둬요. 바꿀 때는 5차와 달라지는 것이므로 따로 검토를 받아요.

## 5차와 달라진 동작 (의도한 것만)

| 무엇 | 5차 | 지금 | 이유 |
| --- | --- | --- | --- |
| 화면 주소 | `#roadmap:id` 해시 | `/roadmaps/id` 경로 | 위 표 참고 |
| 부서장 소속 직원 목록 | 로그인 때 한 번 + 목록 화면에서 다시(목록 화면은 끝없이 다시 부르는 버그가 있었음 · 10/26 원본도 고침) | 부서장 화면에 들어갈 때 한 번 | 쓰는 곳이 부서장 화면뿐이라 중복 요청을 없앴어요. |
| 로그아웃·초기화 뒤 서버 데이터 캐시 | 화면별 변수에 남음 | 모두 비움 | 다른 계정의 부서원·관리자 데이터가 잠깐이라도 보이지 않게 |
| 작성 문서 자동 저장의 `genCur` | 3안 화면 상태를 늘 함께 보냄 | 바뀐 때만 보냄 | 백엔드가 같은 값을 받아도 고른 안을 지우는 문제를 피해요(백엔드 요청 B-4). |
| 관리자 규정 데이터 | 규정·조항 표, 엑셀·CSV와 한 건 고치기(조항을 고치면 새 버전), 규정 색인 만들기 | 원문 PDF 올리기(메모 선택)·올린 PDF 목록·잘못 올린 PDF 삭제·지금 규정 PDF 내려받기만(`/admin/regulations`) | 사용자 결정(2026-10-26): 규정은 벡터 DB를 거친 RAG에 쓰여서 관리자가 고치지 않고, 올린 PDF는 서비스 운영팀이 받아 임베딩해요. 조항 표는 원문과 맞춰 보기 어려워 원문 PDF로 봐요 |
| 빌드 파일 | 매번 다시 받음(no-cache) | 내용 해시 이름으로 오래 캐시, 라이브러리는 따로 묶음 | 배포 때 바뀐 파일만 다시 받게 |

## 알려진 한계·정리 후보

- ESLint 경고 37건(`react-refresh/only-export-components`): 화면 파일이 함수도 함께 내보내 개발 중 핫 리로드가 그 파일만 새로 고치지 못하고 전체를 새로 고쳐요. 동작에는 영향이 없어요. 함수를 별도 파일로 빼면 사라지지만 5차 모듈 단위를 유지하려고 이번에는 그대로 뒀어요.
- 큰 파일: `features/draft/*`·`features/roadmap/*` 일부는 5차 한 덩어리를 옮긴 것이라 길어요. 기능을 고칠 때 나눠요.
- CSS는 전역 파일 3개 그대로예요. 화면별 CSS 모듈로 나누는 것은 모양이 바뀔 위험이 있어 이번 범위에서 뺐어요.
- 서버가 돌려주는 5차 화면 ID에 기대는 곳이 있어요([API 계약](API_계약.md#5차-화면-id가-남아-있는-곳)).
